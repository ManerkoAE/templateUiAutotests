# templateUiAutotests

Портфолио проекта, демонстрирующее эффективную автоматизацию тестов с параметризованными тестами для UI-приложений на основе Selenium и Allure.

## Особенности
- **Параметризованные тесты**:
  - Использование `@ValueSource` для проверки различных доменов при регистрации (mail.ru, gmail.com, yandex.ru, rambler.ru, outlook.com)
  - Проверка валидации формата email через `@EnumSource` (NO_AT_SYMBOL, NO_DOMAIN, DOUBLE_AT, SPACE_INSIDE)
- **Конфигурация**:
  - Использование Lombok и Maven для управления зависимостями
  - Структура проекта с разделением на страницы и тесты
- **Отчеты**:
  - Всё содержимое тестов генерирует отчеты в Allure

## Как запустить тесты
1. Убедитесь, что установлены зависимости через Maven
2. Запустите тесты:
```bash
mvn clean test
```

## Примеры тестов

**Позитивный тест**:
```java
@Story("Регистрация с валидным доменом")
@Description("Проверка регистрации при использовании домена mail.ru")
public class RegistrationDomainValueSourceTest {
    // Тестовый код с параметризацией через ValueSource
}
```

**Негативный тест**:
```java
@Story("Регистрация с невалидным email")
@Description("Проверка валидации формата email")
public class RegistrationEmailEnumSourceTest {
    // Тестовый код с параметризацией через EnumSource
}
```

## Агент правок по комментариям (issue и PR)

В репозитории настроен агент, который читает комментарии к issue и PR, распознаёт команды `/agent` и `/агент` и вносит правки в код через GitHub Models. Используется только встроенный `GITHUB_TOKEN` — сторонние API-ключи не нужны.

Составляющие:
- Workflow: `.github/workflows/agent.yml`
- Скрипт: `.github/agent/agent.mjs`

### Как пользоваться

Напишите в комментарии к issue или PR одну из команд:

- `/agent <инструкция>` — агент подготовит и применит правки к коду;
- `/агент <инструкция>` — то же самое кириллицей;
- `/agent план <инструкция>` — только анализ и план изменений, без правок;
- `/agent` без инструкции — агент пришлёт подсказку по формату.

Пример:

```bash
/agent добавь негативный тест на пустой email в RegistrationEmailEnumSourceTest
```

Как агент обрабатывает запрос:

- **Комментарий к PR** — правки дописываются в ветку этого PR. Для PR из форков правки не применяются: у встроенного `GITHUB_TOKEN` нет прав на запись в чужой репозиторий.
- **Комментарий к issue** — агент создаёт ветку `agent/issue-<номер>-<метка>` и отдельный PR с заголовком «Агент: правки по issue #N».
- **Отчёт** — агент отвечает в ветке комментария и ставит реакции: 👀 (взял в работу), 👍 (план или правки не нужны), 🚀 (правки применены).

Команды выполняются только для авторов с правами OWNER / MEMBER / COLLABORATOR; комментарии ботов игнорируются.

### Переменные репозитория

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AGENT_MODEL` | Модель GitHub Models для анализа и генерации правок | `openai/gpt-4o-mini` |
| `AGENT_ALLOWED_LOGINS` | Дополнительные логины через запятую, которым разрешены команды | — |
| `AGENT_DRY_RUN` | `1` / `true` / `yes` / `да` — принудительный режим плана без применения правок | — |

Ограничения безопасности: агент не изменяет файлы в `.github/workflows/`, `.github/agent/`, `.git/`, `.idea/`, `target/`, `allure-results/`, `.allure/`; за один запуск применяется не более 15 правок, а содержимое одного файла не превышает 100 000 символов.
